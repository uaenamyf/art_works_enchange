# 数字产品前端 UI 方案

## 设计方向

数字产品不是实体商品页面删掉地址后的简化版，而是“文件版本和访问权限”优先的交付界面。消费者需要在第一屏确认三件事：买到的是什么文件、何时可以访问、访问权限是否有效。

视觉上继续使用 CreatorHub 的编辑画廊语言：作品封面使用稳定的 `4:5` 比例，交付信息采用轻量的横向信息条，不使用电商式促销徽章或嵌套卡片。实体产品保留地址、库存和物流信息；数字产品改为文件格式、大小、版本、授权状态和下载操作。

## 页面排版

### 作品详情

桌面端保持左侧作品画廊、右侧交易信息的两列结构。右侧价格下方增加“数字交付”信息条，展示文件类型、文件数量和支付后可访问。移动端先展示封面、标题和价格，再展示交付信息，购买按钮保持 44px 以上触控高度。

### Studio 数字产品编辑

使用两列工作区：左侧是标题、描述、分类和价格，右侧是“交付资产”面板。面板按状态展示 `待上传 → 扫描中 → 可发布 → 已发布`，显示文件名、大小、版本和扫描结果；原始 object key、签名 URL 和下载 Token 永不展示。

### 结算

结算页顶部显示产品类型和交付说明。`PHYSICAL` 显示地址表单与库存提示；`DIGITAL` 不渲染地址字段、不发送空地址对象，数量默认 1 且限制为 1。摘要区域改为“支付确认后生成授权”，创建订单后进入订单详情，而不是显示物流预期。

### 订单详情

实体订单展示收货信息和物流时间线。数字订单展示授权状态：`待生成`、`可下载`、`已撤销`、`处理中`；授权有效时显示文件名、版本和大小，并提供“获取下载链接”按钮。按钮请求短期凭证，成功后仅在当前页面内使用，过期后重新申请。

## 状态与交互

所有数字交付页面覆盖加载、空、错误、处理中和成功状态。下载按钮在请求期间禁用，重复点击使用客户端请求锁；服务端仍必须用授权和对象级权限做最终校验。撤销或扫描失败时不能显示可下载按钮，而是展示明确的状态和支持入口。

## 响应式验收

- `375px`：单列布局，地址区完全不出现在数字结算页，下载操作不产生横向滚动。
- `768px`：订单摘要和授权状态保持同一信息层级，不让文件信息被折叠到不可见区域。
- `1440px`：作品封面、交易信息和交付状态有稳定宽度，页面不使用超大 Hero 或装饰性浮层。
